# KOOK 与 Telegram 原生接口

在对应平台的消息或事件脚本中，红色问答自动选用触发事件的机器人。CRON 等没有来源的脚本先用【设置来源】指定机器人。将示例 ID、文件路径和音源地址替换为实际值。

```text
【设置来源@机器人平台@telegram】
【设置来源@机器人ID@123456789】
```

KOOK 的平台名为 `kook`。

逐项对照官方方法和事件，以及各项的接入状态，见[官方接口对照清单](/adaptar/native-bot-api-coverage.md)。

## 传参与返回值

功能命令按位置填值。省略中间参数时保留空位，末尾可直接省略。列表用【数组】。在文本中保留空格或写入 `@` 时，可用 RedLang 原始字符串，例如 `【@活动通知 A】` 或 `【@@channel_name】`。底层调用的参数和下表返回字段见[通用协议命令参考](/detailref/README.md#telegram调用)。

| 返回字段 | 含义 |
| --- | --- |
| `status` | `ok` 或 `failed`。 |
| `retcode` | 成功为 `0`，平台拒绝时保留错误码，本地请求失败为 `-1`。 |
| `data` | Telegram 的 `result` 或 KOOK 的 `data`，可用【取元素】读取。 |
| `message` | 平台或适配器返回的说明。 |
| `parameters` | Telegram 附带的错误参数，例如限流后的 `retry_after`。 |
| `redreply_message_id` | Telegram 返回消息时或 KOOK 成功创建聊天消息时提供，可用于【撤回】等命令。 |

原生调用使用平台 ID。调用失败时先读取 `retcode` 和 `message`，成功后再读取 `data`。字段和权限要求见 [Telegram Bot API](https://core.telegram.org/bots/api) 和 [KOOK 开发者文档](https://developer.kookapp.cn/doc/reference)。

## Telegram 公共发送选项

【输出流@内容@键盘@话题ID@话题类型@商务连接ID@商务对方ID@发送选项】

发送选项可整项省略。需要时填【数组@静默@内容保护@消息效果ID@建议帖选项@临时消息选项@引用选项】。如只填后面的参数，中间的位置用空项保留。

| 参数 | 填法、是否可省及默认值 |
| --- | --- |
| 静默 | 填真或假，省略默认假。填真时收到无声通知。 |
| 内容保护 | 填真或假，省略默认假。填真时 Telegram 限制转发和保存。 |
| 消息效果 ID | 填 Telegram 效果的正整数 ID，只用于支持此选项的私聊消息。省略时无效果。付费媒体省略本项。 |
| 建议帖选项 | 省略时普通发送。填【数组】提交免费建议帖，或填【数组@币种@价格@发布时间】。币种填星币或 TON，只填价格时默认星币。星币价格填 5 至 100000 的整数，TON 价格以纳克计，填 10000000 至 10000000000000 的整数。币种和价格都留空时免费。发布时间可省，由审核者在 30 天内决定。填写时用当前时间之后 300 至 2678400 秒之间的 Unix 秒。需要频道私信及话题 ID，可沿用事件话题。每次提交单条文字或平台支持的单条媒体。 |
| 临时消息选项 | 省略时普通发送。填写方式见下文。 |
| 引用选项 | 省略时沿用普通引用方式。第六项的详细写法见下文。 |

静默和内容保护适用于现有文字、媒体、发票、清单和媒体组等发送入口。多段消息逐段应用上述基础选项。建议帖和临时消息各用一次【输出流】发送一条。媒体组和商务清单支持前三项，发票支持前四项，付费媒体支持静默、保护和建议帖。发送私聊使用第三项传发送选项。【Telegram文件】和【Telegram投票】用第八项传发送选项，其中投票支持前三项，【Telegram文件】支持前四项。转发或复制也用第八项，消息效果只用于单条私聊，建议帖只用于单条频道私信。

```text
【输出流@今晚的资料已更新@@@@@@【数组@真@真】】
【输出流@欢迎回来@@@@@@【数组@@@5104841245755180586】】
【输出流@这是一条免费投稿@@456@频道私信@@@【数组@@@@【数组】】】
【输出流@这是付费投稿@@456@频道私信@@@【数组@@@@【数组@星币@25】】】
【Telegram投票@哪天参加？@【数组@周六@周日】@@@@@@【数组@真@真】】
```

### Telegram 建议帖审核

收到 `notice:telegram:suggested_post_info` 时，可用【同意@发布时间】或【拒绝@留言】处理当前建议帖。跨事件操作用【同意@发布时间@平台消息ID@频道私信会话ID@建议帖】或【拒绝@留言@平台消息ID@频道私信会话ID@建议帖】。两个 ID 在建议帖事件中默认当前值，其他场景必填。可省略发布时间，沿用请求中的日期，由 Telegram 处理未指定日期的情况。填写时用当前时间到 2678400 秒内的 Unix 秒。留言可省，默认无留言，最多 128 字。批准需要对应频道的发布权限，拒绝需要管理频道私信权限。

平台还发送 `suggested_post_approved`、`suggested_post_approval_failed`、`suggested_post_declined`、`suggested_post_paid`、`suggested_post_refunded` 通知，关键词均以 `notice:telegram:` 开头。【事件内容@建议帖】可读状态、消息ID、会话ID、币种、价格、发布时间、留言、退款原因和支付金额。各字段随事件类型返回。

```text
【取元素@【事件内容@建议帖】@状态】
【同意】
【拒绝@请补充活动日期】
```

### Telegram 临时消息

临时消息选项填【数组@接收者ID@回调ID@替换原消息】。接收者填用户数字 ID，普通群里两项都省略时默认当前发送者。在按钮事件里两项都省略时默认当前回调，或把回调 ID 填当前。显式填接收者和回调时，接收者必须是按按钮的用户。替换原消息填真或假，默认假，仅可在普通按钮回调中使用。按钮事件仍需用【Telegram应答按钮】确认。通过回调或临时消息回复时，Telegram 要求在 15 秒内发送。群内主动发送需要群管理员权限。选择临时消息时可发送单条文字、支持的单条媒体、静态位置、场所或联系人，键盘使用行内模式。

发送成功后【输出流】返回平台临时消息 ID。接收与编辑事件为 `notice:telegram:ephemeral_message`、`notice:telegram:edited_ephemeral_message`，可用【事件内容@临时消息ID】和【事件内容@临时接收者ID】读取。在这两类事件中回复原群时，【输出流】要求提供临时消息选项。更新使用【编辑消息@临时消息ID@新内容@类型@格式@行内键盘@临时@接收者ID@会话ID】，类型默认文本，也支持说明、键盘、媒体。格式和键盘可以省略。撤回使用【撤回@临时消息ID@临时@接收者ID@会话ID】。三项 ID 在临时消息事件中可省略以沿用事件值，在其他场景需要提供，当前群内可省略会话 ID。

```text
【输出流@只有你能看到@@@@@@【数组@@@@@【数组@123456】】】
【输出流@已收到操作@@@@@@【数组@@@@@【数组@@当前】】】
【Telegram应答按钮】
【编辑消息@临时消息ID@更新后的提示@@@@临时@123456@-100123456】
【撤回@临时消息ID@临时@123456@-100123456】
```

[发送方法](https://core.telegram.org/bots/api#sendmessage) · [建议帖参数](https://core.telegram.org/bots/api#suggestedpostparameters) · [临时消息](https://core.telegram.org/bots/api#ephemeral-messages) · [编辑临时消息](https://core.telegram.org/bots/api#editephemeralmessagetext)

### Telegram 高级引用

发送选项第六项用【数组@平台消息ID@原会话ID@引用片段@位置@找不到仍发送@清单任务ID@投票选项ID@引用格式@富文本引文数组@引用样式数组】。多段输出只把引用附在第一段。可用于【输出流】、【发送私聊】、【Telegram文件】和【Telegram投票】。

| 参数 | 填法与默认值 |
| --- | --- |
| 平台消息 ID | 填正整数，或填当前、留空以取当前事件中的平台 ID。跨会话必填显式平台 ID。回复当前临时消息时还需填临时消息发送选项。 |
| 原会话 ID | 填数字 ID 或频道用户名，默认当前目标会话。商务、频道私信和临时消息不支持跨会话引用。 |
| 引用片段 | 填原文中的精确片段，格式化后最多 1024 字符，可省略。 |
| 位置 | 从 0 开始按 UTF-16 编码单元计数，可省略，由 Telegram 匹配。富文本按各段纯文字用换行连起来计算。 |
| 找不到仍发送 | 填真或假，留空由平台处理。普通同会话默认为假。跨会话、跨话题和临时消息须省略或填假，商务消息须省略或填真。 |
| 清单任务 ID、投票选项 ID | 两项都可省略。需要定位时任选一项。任务 ID 填正整数，可从【事件内容@清单任务】取得。投票选项填平台持久 ID，可从【事件内容@投票选项详情】的选项ID或投票回答事件的【事件内容@投票选项ID】取得。 |
| 引用格式 | 填 Markdown 或 HTML，默认纯文本。Markdown 使用 MarkdownV2。 |
| 富文本引文数组 | 可省略，使用时省略普通引用片段、格式和样式数组。按原顺序填写每段文本，也可用【数组@样式@文本】。样式可填粗体、斜体、下划线、删除线、剧透、下标、上标。公式用【数组@公式@LaTeX正文】。自定义表情用【数组@自定义表情@备用表情@表情ID】。日期时间用【数组@日期时间@显示文字@Unix秒@日期格式】，日期格式可省，默认由平台显示。 |
| 引用样式数组 | 可省略，要指定样式时保留普通引用片段并省略引用格式。每项用【数组@样式@位置@长度@附加值@日期格式】。位置和长度以片段内的 UTF-16 单元计，位置从 0 开始，长度至少为 1。样式可填粗体、斜体、下划线、删除线、剧透、自定义表情或日期时间。自定义表情必填表情 ID 作为附加值，日期时间必填 Unix 秒，日期格式可省。其余样式省略后两项。 |

收到引用消息时，【事件内容@引用】可取片段、位置、手动选择、原会话ID、平台消息ID和临时消息ID。可用字段随平台消息提供。

```text
【定义变量@引用@【数组@当前@@活动将在周六开始@0】】
【输出流@我会参加@@@@@@【数组@@@@@@【变量@引用】】】
【定义变量@带样式引用@【数组@当前@@报名@@@@@@@【数组@【数组@粗体@0@2】】】】
【输出流@收到@@@@@@【数组@@@@@@【变量@带样式引用】】】
```

## Telegram 富文本

【Telegram富文本@内容@格式@从右向左@跳过自动识别@资源数组】生成可交给【输出流】的富文本。

| 参数 | 填法与默认值 |
| --- | --- |
| 内容和格式 | 内容必填。格式默认 Markdown，可填 HTML 或内容块。Markdown 和 HTML 按 Telegram 富文本语法填写。内容块填写由【数组】组成的列表。 |
| 从右向左、跳过自动识别 | 可省，分别默认假。填真时启用对应选项。 |
| 资源数组 | Markdown 或 HTML 可选。每项用【数组@标识@类型@来源@文件名】。标识必填并且唯一，用 1 至 64 位字母、数字、下划线或连字符。类型填图片、视频、音频、文件、动画或语音便笺。来源填 Telegram 文件 ID、HTTP(S) 直链或【读文件】字节集。仅字节集必填文件名。用 Telegram 富文本的资源链接把标识放到正文里。 |

内容块使用【数组@段落@正文】、【数组@标题@正文@级别】、【数组@代码@正文@语言】、【数组@页脚@正文】、【数组@分隔线】、【数组@公式@LaTeX正文】、【数组@锚点@名称】、【数组@引文@正文@出处】或【数组@草稿提示@正文】。标题级别 1 至 6，默认 1。代码语言和引文出处可省。草稿提示用于草稿。其他排版可用 Telegram 富文本 HTML 或 Markdown。

```text
【输出流@【Telegram富文本@**周末活动**请查看报名详情。】】
【输出流@【Telegram富文本@【数组@【数组@标题@安排@2】@【数组@段落@周六上午集合】】@内容块】】
【编辑消息@机器人消息ID@【Telegram富文本@<h2>活动已改期</h2>@HTML】@富文本】
```

【编辑消息】的类型填富文本。常规、行内和临时消息的目标写法与文本编辑相同。行内编辑中的资源表只能使用已有文件 ID。收到或编辑富文本会触发 `notice:telegram:rich_message` 或 `notice:telegram:edited_rich_message`，可用【事件内容@富文本】读取正文和从右向左。

【Telegram富文本草稿@富文本@草稿ID@允许停止@停止时保留@私聊ID@话题ID】发送私聊草稿。富文本必填。草稿 ID 填非零整数，更新同一草稿时复用此 ID。两个开关默认假。私聊 ID 与话题 ID 可省，默认当前私聊及同一会话的话题，从群里调用时请指定私聊 ID。草稿约 30 秒后消失，发布最终内容用【输出流】。用户停止后可在 `notice:telegram:stopped_message_generation` 中用【事件内容】读取草稿ID、草稿会话ID或草稿话题ID。

```text
【Telegram富文本草稿@【Telegram富文本@**正在准备活动说明**】@101@真】
【事件内容@草稿ID】
```

[Telegram 富文本格式](https://core.telegram.org/bots/api#rich-formatting-options) · [富文本草稿](https://core.telegram.org/bots/api#sendrichmessagedraft)

## Telegram 菜单

### 命令菜单

- 【Telegram命令菜单@设置@命令数组@范围@语言@聊天ID@成员ID】
- 【Telegram命令菜单@查询@范围@语言@聊天ID@成员ID】
- 【Telegram命令菜单@删除@范围@语言@聊天ID@成员ID】

| 参数 | 怎么填 |
| --- | --- |
| 操作 | 必填 `设置`、`查询` 或 `删除`。 |
| 命令数组 | 设置时必填，每项是【数组@命令名@说明@临时】，最多 100 项。名称可以带开头的斜杠，主体用 1 至 32 个小写字母、数字或下划线。说明填 1 至 256 字。临时可省，默认假。填真时，只有命令发送者与机器人可见。 |
| 范围 | 可省略，默认对所有用户生效。可填 `默认`、`所有私聊`、`所有群聊`、`所有群管理员`、`指定聊天`、`指定群管理员` 或 `指定群成员`。 |
| 语言 | 可省略，表示该范围内没有专门语言设置时使用此菜单。简体中文常用 `zh`，英文用 `en`。 |
| 聊天 ID | `指定聊天`、`指定群管理员` 或 `指定群成员` 时必填，其余范围省略。用户名须带 `@`，脚本里写作【@@名称】。 |
| 成员 ID | 仅 `指定群成员` 时必填。 |

设置、删除成功时没有输出。查询返回命令名和说明。要保留临时开关，用【Telegram命令菜单@查询详情】，结果的第三项是逻辑值，可交给另一条设置命令。删除时填写与设置相同的范围和语言。在群内处理临时命令时使用 `notice:telegram:ephemeral_message` 事件，并用【输出流】的临时发送选项回复。

```text
【Telegram命令菜单@设置@【数组@【数组@help@私下查看帮助@真】】@所有群聊】
【Telegram命令菜单@查询详情@所有群聊】
```

```text
【Telegram命令菜单@设置@【数组
  @【数组@start@开始使用】
  @【数组@help@查看帮助】
】@所有私聊@zh】
```

```text
【取长度@【Telegram命令菜单@查询@所有私聊@zh】】
```

### 私聊菜单按钮

【Telegram菜单按钮@类型@私聊ID@按钮文字@小程序链接】

| 参数 | 怎么填 |
| --- | --- |
| 类型 | 必填 `命令`、`默认`、`小程序` 或 `查询`。分别用于打开命令菜单、恢复默认、打开小程序和读取当前设置。 |
| 私聊 ID | 可省略，省略时操作机器人的默认按钮。指定单个私聊时填数字 ID。 |
| 按钮文字、小程序链接 | 类型为 `小程序` 时必填，链接用 HTTPS。其他类型省略。 |

查询返回三个位置，依次为类型、按钮文字和链接，普通按钮的后两项为空。

```text
【Telegram菜单按钮@小程序@@打开服务@https://example.org/app】
```

### 机器人资料

【Telegram机器人资料@查询@资料项@语言】返回文字。【Telegram机器人资料@设置@资料项@新文字@语言】修改资料。资料项必填，可填 `名称`、`简介` 或 `短简介`，长度上限分别为 64、512 和 120 字。语言可省略，默认通用资料，指定语言时填两字母代码，例如 `zh`。设置时留空文字可移除对应语言的资料。

```text
【Telegram机器人资料@设置@短简介@查看活动和通知@zh】
```

## Telegram 行内键盘与回复键盘

【Telegram键盘@按钮行数组@模式@自动缩放@用后隐藏】

## Telegram 发票、支付与退款

Telegram 内销售数字商品和数字服务使用星币。实体商品和服务使用在 BotFather 配置的支付服务商令牌和受支持的货币。实体订单的退款由相应支付服务商处理。示例中的订单识别值需替换成你系统中的订单号。

### 发送发票与生成链接

【Telegram发票@商品名@商品说明@订单识别值@金额或价格明细@币种@服务商令牌@附加选项】生成发票消息，用【输出流】发送并取得 RedReply 消息 ID。

| 参数 | 怎么填 |
| --- | --- |
| 商品名、商品说明 | 均必填，分别为 1 至 32 字和 1 至 255 字。 |
| 订单识别值 | 必填，1 至 128 字节，用于在支付事件中匹配订单。 |
| 金额或价格明细 | 必填，可填正整数总价。分项时写【数组@【数组@名称@整数金额】@…】，允许负数折扣，总额必须大于 0。星币只允许一项。其他币种填最小货币单位整数，例如 145 表示 1.45 美元。 |
| 币种、服务商令牌 | 币种默认 `星币`，也可填 `XTR`。星币的令牌留空。其他币种填三字母大写货币代码及对应令牌。 |

| --- | --- |

| 图片链接 | 可省略，填商品图片的 HTTP(S) 直链。 |
| 小费选项 | 实体支付可选【数组@上限@建议金额一@…】。整数金额按货币最小单位填写，最多四个依次递增且不超过上限的建议值。省略时不收小费。 |
| 服务商自定义资料 | 实体支付可选【对象】，成员名和结构由支付服务商自行约定。常用发票可省略。 |
| 图片规格 | 可省略，格式【数组@宽度@高度@字节数】。各项可留空，填写时使用正整数，并同时提供图片链接。 |
| 启动参数 | 仅普通发票可填。留空会保留转发副本的支付按钮。填写后，转发副本引导用户用此参数启动机器人。 |
| 是否订阅、商务连接 ID | 仅星币发票链接可填，分别默认 `假` 和空。订阅周期固定 30 天，每期最多 10000 星币。代商务账户生成链接时填写连接 ID。 |

### 运费询价、结账审核与支付事件

| 事件关键词 | 能读取什么或做什么 |

| `notice:telegram:shipping_query` | 读取订单和配送地址。用【同意@配送方式数组】返回至少一种配送方式，或用【拒绝@原因】告知用户无法配送。 |
| `notice:telegram:pre_checkout_query` | 按订单校验用户、币种、金额、库存及配送方式，10 秒内用【同意】或【拒绝@原因】应答。拒绝原因必填。 |



## 编辑、转发和批量撤回

【输出流】返回 RedReply 消息 ID，可以存入变量供后续脚本操作。以下命令使用这个 ID。【Telegram调用】和【KOOK调用】的原生方法仍使用平台 ID。一个 RedReply ID 可能包含多条平台消息，例如一次输出发送多段内容。编辑需要单条消息 ID。转发和撤回可展开多段消息。

### 编辑消息

【编辑消息@消息ID@新内容@类型@文本格式@行内键盘@目标类型】

省略第一个参数时使用当前消息。类型省略时为 `文本`。返回对象包含 `retcode`、`data` 和 `message`。

| 平台 | 类型与参数 |
| --- | --- |
| Telegram | `文本` 和 `说明` 接受文本。`键盘` 传【Telegram键盘】，新内容留空时清除按钮。`媒体` 传【数组@媒体类型@来源@说明@文件名】，类型和来源可按【媒体组】填，也可填动画。说明可省，默认无说明。字节集来源要填文件名，文件 ID 或直链的文件名留空。 |
| KOOK | `文本` 接受 KMarkdown。`卡片` 传【KOOK卡片】。适配器按原消息选择频道或私聊编辑接口。 |

```text
【定义变量@消息ID@【输出流@活动开始时间待定】】
【定义变量@结果@【编辑消息@【变量@消息ID】@活动将于周六开始】】
【取元素@【变量@结果】@retcode】
```

Telegram 可选格式填 `Markdown`（MarkdownV2）、`HTML`，或留空发普通文本。第五项可选传【Telegram键盘】生成的行内键盘。第六项留空时第一项使用 RedReply 消息 ID。要编辑 Telegram 行内消息时，第六项填 `行内`，第一项填平台行内消息 ID，媒体使用已上传的文件 ID 或支持的直链。

第四项也可填【数组@格式@链接预览@说明在上方】。格式默认纯文本。文本的链接预览用【数组@关闭@链接@尺寸@放在上方】，均可省略。两个开关默认假，链接默认正文里的第一个网址，尺寸可填大或小，默认由 Telegram 决定。说明在上方可填真或假，默认假，用于图片、视频和动画的说明。

```text
  @【数组@查看活动@event-details】
```

### 转发消息

【转发消息@消息ID或数组@目标ID@目标类型@是否复制@是否静默@话题ID@话题类型】

源 ID 省略时使用当前消息。目标省略时使用当前会话，跨会话时填写目标 ID，KOOK 私聊同时指定 `私聊`。Telegram 可使用聊天 ID 或 `【@@频道用户名】`。该命令转发已存在的消息，【合并转发】仍用于生成现有的合并消息节点。

- **Telegram** 使用 `forwardMessage` 或 `forwardMessages`。批量最多 100 条，需来自同一普通聊天，按平台消息 ID 升序发送。服务消息和受保护消息由 Telegram 限制。是否复制和是否静默分别默认 `假`，需要时填 `真`。复制后省去原转发来源。话题 ID 可省略，默认同一会话的当前话题。指定话题 ID 时，话题类型默认 `话题`，也可填 `频道私信`。数字目标的返回对象提供 `redreply_message_ids`，可逐条编辑或撤回。批量接口可能跳过不能转发的消息。
- **KOOK** 公开接口提供消息读取和发送。适配器读取原消息内容后重新发送文字、KMarkdown、卡片和常见附件，由机器人署名，卡片按钮的回调也会发给重发卡片的机器人。发送失败时，`data.sent` 保留此前已发送的 RedReply 消息 ID，可避免重试时重复发送。

```text
【取元素@【变量@结果】@retcode】
```

### 批量撤回

【撤回@<font color="red">RedReply 消息 ID 数组</font>】

Telegram 按原聊天分组，每次原生请求最多 100 条，使用 `deleteMessages`。业务消息按聊天和业务连接分组，使用 `deleteBusinessMessages`。KOOK 按每条消息的频道或私聊类型选择删除接口。两端均去重，单项失败后继续处理剩余请求。返回 `data.failed` 为失败请求数，`data.results` 内每项含目标和平台响应。Telegram 跳过已不存在的消息，因此成功表示该批请求被平台接受。单条文本 ID 的【撤回】用法保持原样。

```text
【定义变量@结果@【撤回@【数组@消息一ID@消息二ID】】】

```

### 用 KOOK 卡片发起投票

KOOK 的公开 Bot API 提供卡片按钮及其回调。用下面的脚本在频道发起投票。

```text
【隐藏@【输出流@【KOOK卡片@下次活动选哪天？@【数组@【数组
  @【数组@周六@poll-weekend-sat】
  @【数组@周日@poll-weekend-sun】
】】】】】
```

```text
【定义变量@选择@【事件内容@按钮值】】
【定义变量@投票ID@【事件内容@平台消息ID】】

  @【写配置@【应用目录】kook-votes.ini@【变量@投票ID】@【发送者ID】@周六】
】
【解锁@kook-votes.ini】
```

【加锁】和【解锁】避免同包中的投票事件同时写配置。统计脚本使用同一个锁，可用 `【读配置键@【应用目录】kook-votes.ini@原生消息ID】` 读取各人的选择，再用【循环】按选项计数。[KOOK 按钮事件](https://developer.kookapp.cn/doc/event/user)
